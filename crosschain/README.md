# BSC → Elys 跨链兑付：离线基础模块（不可用于收款或发放）

## 当前状态

只实现与目标链无关的精确数量换算和 SQLite 发放日志，10 项本地测试。**没有实现 BSC 托管/销毁请求合约、跨链证明、Elys 发送适配器、钱包签名或自动发放服务。** 当前同链 RedeemVault 未修改，不能拿它冒充跨链兑换合约。

尚待用户确认 Elys 官方公告、目标链标识、接收地址格式、资产及精度。搜索到的同名 Elys Network 有主网历史，无法据此确认用户所说 11 月 3 日上线的链；禁止猜测 RPC、合约地址、资产或确认数。

## 拟定流程（不是已实现功能）

1. 用户连接 BSC 钱包，提交目标链接收地址和兑换数量，看到真币、链、比例、费用、最低到账及失败规则后确认。
2. 独立 BSC 请求合约记录源链、合约、唯一 requestId、用户、目标链/资产、接收地址、实际收到量及精度。不得仅看转账哈希或事件文本。
3. 验证器检查源链执行成功、合约白名单、真实状态和最终性，确认请求不再可退款后才允许目标链付款。未完成请求合约设计前不能开放收款。
4. 目标链适配器核对链身份、地址格式、资产、资金和网络费，使用最小单位整数计算数量。先持久化已签名交易及其派生交易 ID，再广播。
5. 广播超时或服务重启后查询已有交易；状态不明时不另造转账。只有确认目标链成功、收款人/资产/金额符合请求且达到最终性后才登记已付。
6. 展示源/目标链交易及实际到账；重复请求、重复事件、竞争工作进程和重试不能形成第二笔付款。

## 信任模型与退款问题

BSC 不能仅凭一个 Elys 交易哈希验证付款。若目标链没有可用桥/轻客户端证明，首版只能是披露信任的托管发放服务（建议多签管理资金），不能称为无需信任跨链桥。

BSC 锁币与 Elys 付款不原子。不能在“Elys 已发币，但 BSC 状态尚未回写”期间允许超时退款，否则会双领。也不能贸然先销毁用户币再承诺自动退款。请求合约需要明确 pending/cancelled/committed/paid 状态、不可竞争的提交点、承诺后资金保障及人工异常处理；这些取决于目标链能力，尚未选定实现。

本地防重日志只对同一持久化数据库有效，不防管理员另起数据库、手工付款、签名者作恶或两套独立服务重复发送。最终若目标链支持合约，优先使用链上 requestId 去重的兑付合约；否则需要更强的托管运营约束。

## 已实现模块

- `convert_units`：按实际入账量换算，返回尾数；拒绝零到账或超 uint256 金额。只作用于本模块，**没有修复旧 Solidity 合约的溢出残留**。
- `Intent`：源请求身份与目标付款内容分开，阻止同一源请求改地址、资产、金额后绕过日志去重。地址规范化必须由未来的链适配器完成，不能把不一致大小写/编码直接当成不同合约。
- `SettlementJournal`：事务性入队、原子抢占付款准备、签名交易持久化、重启恢复、相同交易不能登记到两个请求。
- `record_verified_payment` 只是未来受信任适配器的内部入口，不验链，不可作为公网 API；测试里的 tx/签名都是假的 fixture。

## 测试

仓库根目录运行 `python -m unittest discover -s crosschain -v`。只用 Python 标准库；不读取私钥、不连接 RPC、不广播交易。测试保留系统临时目录中的数据库，不自动删除文件。

## 继续开发所需信息

- Elys 官方网站及 11 月 3 日上线公告。
- 真币名称、官方发行关系、所在链及资产标识（未公布则等待）。
- 是否有官方桥/验证接口、链是否兼容 EVM、交易最终性和收款地址规则。
- 备货来源及数量、托管/多签负责人和可公开的兑付承诺。

以上确认后才可实现和测试真实适配器、选择源链托管模型，最后进行双链测试网 E2E。尚未部署、未收用户币、未创建钱包或签名交易。本模块不是安全证明或官方映射认可。
